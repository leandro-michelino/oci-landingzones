# CDN Static Asset Distribution

Use this blueprint when an application team needs secure document delivery and
low-latency static asset distribution from OCI Object Storage without exposing
storage credentials. It creates the OCI origin, short-lived PAR test path, and
optional Cloudflare edge resources for cacheable public-safe assets.

## At A Glance

| Item | Details |
| --- | --- |
| Folder | `blueprints/extensions/cdn-static-assets` |
| Best fit | Private Object Storage origin with short-lived PAR downloads and Cloudflare at OCI edge hand-off for cacheable assets. |
| Terraform shape | Object Storage bucket, sample objects, lifecycle rules, smoke-test PARs, optional OCI DNS CNAME, optional Cloudflare DNS/cache/Worker resources, IAM policy shell. |
| Default posture | Bucket is private with `NoPublicAccess`; sample objects, lifecycle, DNS, and PARs are explicit toggles. |
| Customer paths | Extension-only beside an existing app backend, or base-plus-extension after Core, Networking, and DNS ownership are ready. |

## Choose The Path

| Path | Use When | Main Sample |
| --- | --- | --- |
| PAR-only private downloads | The application backend will generate short-lived PARs and return them to authenticated users. | `samples/par-only-existing-bucket.tfvars.example` |
| Cloudflare at OCI hand-off | OCI owns the origin contract and the edge team provisions Cloudflare at OCI through the OCI partner flow. | `samples/cloudflare-handoff.tfvars.example` |
| Full external Cloudflare smoke test | You have a Cloudflare account, zone, and API token and want Terraform to prove DNS, cache rule, Worker, route, OCI bucket, PAR, and cleanup end to end. | `samples/cloudflare-worker-full.tfvars.example` |

For production, keep customer authentication in the application layer. Use
Terraform-managed PARs only for demos and smoke tests; generate real PARs at
request time from a backend service.

## Does This Still Make Sense?

Yes, with one update: treat Cloudflare at OCI as the preferred OCI-aligned edge
path for CDN, WAF, DNS, and cache controls. Do not model a generic native
`oci_cdn_*` resource because the OCI Terraform provider does not expose one for
this pattern. The blueprint also supports a customer-owned Cloudflare account
for labs and external-provider deployments.

Use two delivery paths:

| Asset Type | Delivery Model |
| --- | --- |
| Sensitive PDFs, statements, health records, and per-user documents | Backend generates short-lived Object Storage PARs, usually 15 minutes or less. Return the PAR directly or redirect once. Set `Cache-Control: private, no-store`. |
| Public-safe JS, CSS, images, and immutable media | Publish under approved prefixes such as `public/`, then front the approved origin model with Cloudflare at OCI or customer-owned Cloudflare. |

## Use Cases

| Use Case | Why This Blueprint Fits |
| --- | --- |
| Customer document download | Keeps the bucket private and uses short-lived ObjectRead PARs instead of sharing OCI credentials. |
| Static asset acceleration | Produces an Object Storage origin contract and optional DNS hand-off for Cloudflare at OCI. |
| Regulated asset handling | Separates private/no-store objects from public-cacheable prefixes. |
| CDN migration planning | Captures the OCI-side state boundary while Cloudflare subscription, rules, and activation stay in the edge control plane. |
| Smoke-testable origin | Can upload synthetic objects and create a test PAR for end-to-end validation. |

## Inputs To Decide

| Input | What To Decide |
| --- | --- |
| `compartment_ocid` | Where the origin bucket, optional DNS record, and optional policy live. |
| `create_asset_bucket`, `existing_asset_bucket_name` | Whether this blueprint owns the bucket or references an approved existing origin bucket. |
| `kms_key_id` | Whether customer-managed Vault keys are required for the bucket and sample objects. |
| `create_sample_objects` | Whether to create synthetic assets for validation. |
| `preauth_requests` | Demo-only PARs for smoke tests. Runtime PARs should be generated by the backend broker sample or an application service. |
| `cdn_mode`, `cdn_hostname` | Whether the edge hand-off is Cloudflare at OCI, external Cloudflare, or PAR-only. |
| `create_dns_cname` | Whether OCI DNS owns the public zone and can point the CDN hostname to Cloudflare. |
| `create_cloudflare_worker_proxy` | Whether Terraform should create a Cloudflare Worker route that hides a smoke-test OCI PAR behind the Cloudflare hostname. |
| `cloudflare_account_id`, `cloudflare_zone_id` | External Cloudflare account and zone identifiers for DNS, cache rules, Workers, and routes. |

## Recommended Deployment Order

1. Confirm the asset classes: private documents, public static assets, or both.
2. Deploy or select the private Object Storage origin bucket.
3. Enable synthetic samples and a demo PAR only for test environments.
4. Deploy the backend PAR broker for sensitive downloads.
5. Provision Cloudflare at OCI through OCI Partner Offerings or use an existing Cloudflare account.
6. Configure Cloudflare cache rules only for approved public-safe prefixes.
7. Destroy smoke-test PARs and synthetic objects after validation.

## Terraform Quick Start

```bash
cd blueprints/extensions/cdn-static-assets
cp terraform.tfvars.example terraform.tfvars
terraform init -backend=false
terraform plan -var-file=terraform.tfvars
terraform apply -var-file=terraform.tfvars
```

Test the synthetic private object through the Terraform-managed PAR:

```bash
terraform output -json preauth_request_urls | jq -r '.statement_demo'
curl "$(terraform output -json preauth_request_urls | jq -r '.statement_demo')"
```

The `preauth_request_urls` output is sensitive. Protect generated output files,
CI logs, and local test workspaces because PAR URLs are bearer credentials.

## Full Cloudflare Test

Use `samples/cloudflare-worker-full.tfvars.example` when a real Cloudflare
account is available and the test should include Cloudflare DNS, cache rules,
Worker script, Worker route, and a Cloudflare-routed `curl` smoke test.

Required Cloudflare inputs:

| Input | Where It Is Used |
| --- | --- |
| Account ID | Worker script deployment. |
| Zone ID | DNS record, cache ruleset, and Worker route. |
| API token | Provider authentication through `CLOUDFLARE_API_TOKEN`; never store this in tfvars. |
| Disposable hostname | Cloudflare proxied DNS record and Worker route, such as `assets.example.com`. |

The API token needs the equivalent of DNS edit, Zone Rulesets edit/read,
Workers Scripts edit/read, and Workers Routes edit/read for the selected
account and zone.

The full Cloudflare smoke path intentionally uses a Worker because it keeps the
OCI PAR URL in a Worker secret binding and returns only the customer-facing
Cloudflare URL to the client. The origin-rule path is still modeled, but Host
Header override can be entitlement-dependent in Cloudflare accounts; keep
`create_cloudflare_origin_ruleset = false` unless that feature is approved for
the zone.

Run the full test:

```bash
export CLOUDFLARE_API_TOKEN="<cloudflare-api-token>"

CDN_STATIC_ASSETS_LIFECYCLE_CONFIRM=true \
CDN_STATIC_ASSETS_VERIFY_CLOUDFLARE=true \
  scripts/test-cdn-static-assets-lifecycle.sh \
  --var-file .leo-local/cdn-static-assets-cloudflare.tfvars \
  --profile NON_DEFAULT_TEST \
  --region us-ashburn-1
```

## Real Lifecycle Test

This blueprint includes a repository-level real lifecycle runner:
`scripts/test-cdn-static-assets-lifecycle.sh`. It performs:

1. `terraform fmt -check`, `init`, `validate`, `plan`, and `apply`.
2. OCI CLI readback for the bucket and synthetic objects.
3. OCI CLI readback for the Terraform-managed PAR.
4. A real `curl` download through the PAR URL.
5. Optional Cloudflare DNS/cache/Worker API readback and proxied `curl`.
6. `terraform destroy` and a post-destroy state check.

Prepare an ignored local tfvars file from the sample:

```bash
mkdir -p .leo-local
cp blueprints/extensions/cdn-static-assets/samples/real-lifecycle.tfvars.example \
  .leo-local/cdn-static-assets.tfvars
```

Edit the OCIDs, region, profile, and bucket name, then run:

```bash
CDN_STATIC_ASSETS_LIFECYCLE_CONFIRM=true \
  scripts/test-cdn-static-assets-lifecycle.sh \
  --var-file .leo-local/cdn-static-assets.tfvars \
  --profile NON_DEFAULT_TEST \
  --region us-ashburn-1
```

The runner destroys resources by default. Use `--keep-resources` only for a
review window.

The committed real-test sample keeps Object Storage lifecycle policy creation
disabled for broad tenancy compatibility. Enable `create_lifecycle_policy` only
when the target compartment has the required Object Storage service-principal
IAM policy.

## Backend PAR Broker Sample

Use `samples/python-par-broker` for a real backend example that generates
short-lived PAR URLs at request time. The sample reads `OCI_ASSET_BUCKET`,
`OCI_OBJECT_STORAGE_NAMESPACE`, and `PAR_TTL_MINUTES`, then creates an
ObjectRead PAR for the requested object.
