# OCVS Blueprint Validation / October 28, 2026

## Delivered Scope

`blueprints/vmware/ocvs` creates an optional dense/vSAN SDDC using the nested
initial-configuration schema in `oracle/oci = 9.11.0`. One MANAGEMENT cluster
and at least one explicit WORKLOAD cluster share the chosen single AD, shape,
VMware bundle and commitment. Each cluster has its own existing provisioning
subnet and baseline VLAN set. Host count is constrained to 3-64 per cluster.

Cloud creation and network inspection are disabled by default. The only default
resource is a local `terraform_data.guard`; it is not an OCI resource.
No credentials, actual network identifiers or customer data were used in tests.

The provider/plugin initially could not start in the restricted local execution
context; schema, validation and lint succeeded after enabling local plugin
communication. Ansible syntax checks used `/tmp` for local temporary files.
These were environment corrections, not successful cloud tests.

The 19 mocked plans cover disabled defaults, read-only network lookup selection,
cost acknowledgement, missing network/deployment inputs, repeated VLAN IDs,
wrong compartment/VCN/AD, private provisioning subnet, HCX VLAN prerequisite,
dense-shape scope, minimum host count, display-name limits, required WORKLOAD
cluster, cross-cluster subnet/VLAN separation, nested MANAGEMENT/WORKLOAD
configuration and HCX/BYOL references. The fixture bundle/shape/commitment and
RSA public-key string are fake and must never be used for deployment.

## Explicitly Unverified

No OCI API inventory, real Terraform plan, apply/destroy, VMware login, guest
VM, migration, HCX pairing, workload traffic, backup, DR, quota/capacity or
licensing test was performed. There are no live resources from this task to
clean up. Future real tests must follow the repository's separate authorization,
compartment/region, cost and verified-cleanup rules.

Network metadata lookups check ownership/placement only. They do not establish
Oracle's complete required security/routing/MTU/DNS matrix or non-overlap of
management, workload and remote-site ranges. Commitment/pricing and BYOL
eligibility must be reviewed for the selected offering before any real apply.
